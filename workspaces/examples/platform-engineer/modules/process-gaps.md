# Process gaps

## Process gaps

**Nothing detects an unseen payroll request.** The single largest delay on this hire was five days lost because an automated email went to a spam folder and no one knew. The process budgets twenty-four hours for a payroll rework; this took five days, and it was caught by someone thinking to telephone rather than by anything in the process. It is the third occurrence in six months. A start date survived this time only because the candidate had already moved it out a week for her own reasons.

**The non-standard hardware decision has no defined path.** The process asks the question and stops. On this hire the hiring manager decided on precedent and told the service desk, which worked because the manager was experienced and the precedent existed. Neither is guaranteed. The two days the decision cost were not budgeted in any estimate.

**Building access is outside the provisioning sequence and unaware of it.** Cards are produced in a weekly batch that the provisioning run knows nothing about. Any Monday start will arrive without a card unless someone remembers to request it early.

**One system still provisions by hand.** The observability platform has no directory integration and is created manually for every starter. It has not failed yet; nothing would catch it if it did.

**The role evaluation and advertising steps remain undocumented.** Both were carried out properly on this hire and both are recorded here only because this definition asks for them. There is still no written definition of either, and the record in `role-evaluation.method` is currently the closest thing to one that exists.
