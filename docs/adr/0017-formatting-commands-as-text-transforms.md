# Formatting commands as deterministic plain-text transforms over the lezer tree

The formatting toolbar (#133) and its shortcuts need to apply markdown edits — toggle bold/italic/strikethrough/inline code, wrap or unwrap links, add/remove list markers, blockquotes, headings, rules, fences — from both button clicks and keyboard shortcuts. The obvious implementation reaches for ProseMirror-style commands: parse the document into a node tree, mutate nodes, re-serialize. CodeMirror's markdown support gives us the syntax tree to *read*, but not an editable tree to *write* — CodeMirror is a text editor, and its tree is a derived index over plain text.

We therefore implement every command as a **pure function over plain text plus a read-only syntax-tree query**, in `web/lib/markdownCommands.js`: given `{ tree, text, from, to }`, each command decides what to do by consulting the [lezer](https://lezer.codemirror.net) syntax tree (`@codemirror/lang-markdown` parses it for free — ADR-0004), computes new full-document text and a new selection range, and returns them without touching the DOM or CodeMirror at all. The editor glue (`runMarkdownCommand` in `web/app.js`) reads doc, selection, and `syntaxTree(state)` off the live view, calls one of these functions, and dispatches the result as a single transaction — so buttons and shortcuts are literally the same code path (the keymap handlers call the same `runMarkdownCommand` the buttons do), and every command is exactly one undo step.

The transforms are deliberately boring and total: for any `(text, from, to)` they return some valid result, never throw, and never depend on anything but their inputs. Toggling semantics follow the "smart" behaviour the ticket specifies — any selection intersecting a format node's content range unwraps that whole region (positions are mapped through per-line edit deltas and clamped); an empty cursor lays down a doubled marker pair (`****`) with the cursor between the halves, so typed text lands inside; block decisions (lists, quotes) look at every non-blank line in the span and only remove when all lines already carry the marker, converting conflicting prefixes otherwise; headings set a level rather than toggling it, with re-invoking the current level stripping it; fenced-code detection uses the tree's `FencedCode` nodes when present and falls back to fence-line inspection when the parser hasn't caught up.

The payoff of keeping this layer pure is testability: the whole command vocabulary runs under plain `node --test` with hand-built fake trees (`{name, from, to, parent}` + `resolveInner(pos)`), no browser needed. The fake tree mirrors just the two things the commands read — node names and source ranges — which is also the honest statement of the coupling: these commands depend on lezer's node naming (`StrongEmphasis`, `Emphasis`, `Strikethrough`, `InlineCode`, `Link`, `BulletList`, `OrderedList`, `Blockquote`, `ATXHeading1..6`, `FencedCode`) and nothing else about CodeMirror.

Alternatives considered and rejected:

- **A WYSIWYG rich-text layer (ProseMirror, Milkdown, TipTap) over the same fields.** Rejected: ADR-0004 chose CodeMirror precisely because module files are *plain markdown files on disk* (ADR-0005) that must round-trip byte-for-byte outside the editor; a rich-text layer re-serializes documents on save and would rewrite author formatting wholesale.
- **Regex-only commands, no syntax tree.** Rejected: "is this selection already bold?" is a question about nesting (`**a *b* c**`, emphasis inside emphasis inside lists), and answering it by regex reproduces a parser badly; the tree makes the common cases exact and gives a principled answer for nested spans.
- **CodeMirror language-data / command packages (@codemirror/commands has no markdown formatting).** Rejected: no maintained CodeMirror package provides markdown toggles; the third-party ones couple directly to EditorView instances, which is exactly the dependency that would have made the command layer untestable outside a browser.
- **Toolbar state reflection (highlighting the Bold button when the cursor sits inside bold).** Deferred: the ticket requires self-demonstrating *letters*, not active-state tracking; reflecting format-at-cursor needs incremental tree queries on every cursor move and buys little while the letters themselves show what each button does.

Status: accepted.
