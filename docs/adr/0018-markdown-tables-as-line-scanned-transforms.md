# Markdown tables as line-scanned text transforms with graceful degradation

The table feature (#134, with its trigger moved to the formatting toolbar by #180) needs Loop-style editing inside markdown fields: a hover-grid size picker behind the Table action, a contextual control strip (add/remove rows and columns, per-column alignment), and a keyboard flow — Tab walks the cells, Enter appends a row from the last one — while preview tables render styled in every theme.

ADR-0017's seam already gives us commands as pure functions over `{ tree, text, from, to }`, and tables fit it without extension: every table command is a pure transform in `web/lib/markdownCommands.js` returning new full-document text plus a selection, dispatched as one transaction by the same `runMarkdownCommand` glue. One addition to the contract: **a table command may return `null`, meaning "there is no well-formed table here — do nothing"**, and the glue treats that exactly like an unconsumed keypress (`runMarkdownCommand` returns false so the keymap falls through).

What tables do *not* do is use the lezer tree. `@codemirror/lang-markdown`'s default parser doesn't recognise GFM pipe tables at all, so there is no tree query to make; instead each command re-derives the table from raw lines via `findTable(text, pos)`: scan out from the cursor's line collecting the maximal run of pipe-bearing lines above and below, split each into cells on unescaped `|`, then validate — exactly one delimiter row (`---`, `:--:`, `---:` shapes only), a header immediately above it anchoring where the table begins (lines the scan picked up above the header are prose that merely carries pipes: excluded from every rebuild, and a caret among them means "not in a table"), every row the same cell count, cursor actually inside. The result carries everything downstream commands need: cell text ranges for caret snapping, delimiter index, per-column alignment. This is a deliberate duplication of ~60 lines of pipe-parsing in exchange for zero coupling to CodeMirror internals — the honest statement of the dependency is "lines of text", which is also why the whole engine tests under plain `node --test` with string fixtures, no browser.

Strictness policy: **graceful degradation, not modal trapping.** A ragged or ambiguous run of pipe lines parses to `null`, and every command — strip buttons included — becomes a silent no-op on it. The keyboard layer compounds this: Tab/Shift-Tab consume the keystroke only when `findTable` succeeds under the caret, so indenting still works everywhere else; Enter hijacks nothing except from the last cell of the last row, where it appends a row instead of splitting a line. Deleting the last remaining column deletes the whole table (Loop's convention), deleting the header promotes the first body row into its place, and a fresh cell's padding borrows its neighbour column's width so existing edges stay aligned byte-for-byte — rebuilds preserve interior padding exactly, normalising only the outer pipes.

The picker semantics are presentation-layer: the grid's hovered rectangle counts the header, so picking 3×2 means header + one body row; the UI translates that to the engine's body-row count at the call site rather than the engine growing a second meaning of "rows".
