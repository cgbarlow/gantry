# One document heading scale: module titles at `#`, field headings at `##`, author content from `###`

The markdown a module file and its rendered artefacts use for headings grew by accretion, and the levels no longer lined up across the three places headings exist. Inside a module file, the writer emitted only `## <field title>` sections — no module title at all — so an author writing their own `##` sub-heading inside a field's prose collided with the parser's field-boundary detection (a stray one became an "unknown section" warning, or a strict-mode error). In the rendered artefacts, the document title took `#`, each module title `##`, and each field heading `###` — two levels deeper than the same field sat in the module file it came from.

We adopt one scale everywhere (the rescaling #130 introduces, ahead of #129's editing work): **the module title is `#`, every field heading is `##`, and author content starts at `###`.** A module file now leads with its own title at `#` after the frontmatter; artefact templates render each module title at `#` and each field heading at `##`; and everything an author writes inside a field begins at `###` or deeper. The practical payoff is that structural headings and author headings can never be confused with each other again — the parser keys fields off exactly `##`, authors get `###`-and-below as their own space, and a rendered document reads its defined sections as H1s.

Existing module files are migrated lazily, on read (`migrateModuleHeadingScale`, `lib/instance.js`) — the same migrate-on-read-and-write-back pattern ADR-0010 used for the workspace subdirectory layout, chosen for the same reason: instances live in repos this code doesn't control (ADR-0005), so there is no single moment or place where a batch migration could run. A file is recognized as old-scale by the absence of a `# <module title>` heading after its frontmatter; migration inserts that title, keeps every `##` heading that matches a field title where it sits (field headings are `##` in both scales), and demotes any other heading that would collide with the structural levels down to `###` — which is precisely what makes the round-trip lossless: an old file's stray author `##`/`#` headings become ordinary content inside the field they were written under, instead of phantom sections the parser warns about. The Azure-DevOps-backed read path pushes the migrated file back as its own commit; migration write-backs are serialized in-process because concurrent readers of several still-old-scale modules (evaluateStage reads a stage's modules concurrently) would otherwise race their pushes against one branch tip and lose to TF401028. This repo's own fixture instances (`instances/*`) are migrated in the same commit that introduced the scale, so test runs don't mutate fixtures mid-suite.

Alternatives considered and rejected:

- **Keep field headings at `##` in module files but leave artefact templates rendering them at `###`.** Rejected: the whole point of a single named scale is that a given heading level means the same thing in a module file and in the document rendered from it; keeping two scales would preserve exactly the drift this ADR closes.
- **Demote the artefact document title below the module titles instead of leaving it at `#`.** Rejected: the title line carries the instance slug and artefact name, and pandoc maps it to the docx's title styling; multiple H1s in one document are unambiguous here since each module's title is its own H1, and the templates' structure is otherwise untouched.
- **Batch-migrate every known repo up front instead of lazily.** Rejected: gantry has no inventory of external workspace repos beyond what's registered locally, no guarantee of credentials at migration time, and no atomic multi-file push (ADR-0010 weighed the same trade-off) — lazy per-file migration on first read needs none of those and converges on its own.
- **Treat a stray non-field `##` as an error during migration rather than demoting it into content.** Rejected: it was already a warning (or strict-mode error) under the old parser, so erroring adds nothing; demotion preserves the author's words in the field they wrote them under, which is what "migration" promises.

Status: accepted.
